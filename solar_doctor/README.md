# Solar Doctor ☀️ — دكتور الألواح الشمسية

محرك + واجهة بيحوّلوا قراءات إنتاج الألواح الشمسية اليومية إلى قرار بالجنيه: **نظّف الآن / استنى / افحص عطل**.

> ⚠️ **كل البيانات اللي في المشروع حاليًا محاكاة** (مولّدة بالكود). الدقة المذكورة هنا هي دقة على المحاكاة، مش على أنظمة حقيقية.
> قبل ما تدّعوا دقة في الواقع لازم تجربة تنظيف حقيقية (راجع `docs/` وقسم "الخطوة الجاية" تحت).

## تشغيل سريع

```bash
python -m venv .venv && source .venv/bin/activate      # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt
pytest -q                     # لازم يطلع: 16 passed
streamlit run app.py          # الواجهة (بيانات محاكاة افتراضيًا)
python evaluate.py 100        # قياس دقة المحرك على 100 سيناريو محاكاة
```
Python 3.10 أو أحدث. Streamlit 1.50 أو أحدث (الواجهة بتستخدم `width="stretch"`).

## إزاي المحرك بيشتغل (بالبسيط)

1. **أقصى إنتاج ممكن:** pvlib بيحسب لكل يوم إنتاج نظامك لو السماء صافية تمامًا.
2. **مؤشر الأداء:** `الفعلي ÷ أقصى ممكن`. الغيوم بتنزّله يوم أو اتنين بس.
3. **الغلاف العلوي:** بناخد الأيام الصافية (تقريبًا أعلى 15% في كل 7 أيام). الأتربة بتنزّل الغلاف **ببطء**.
4. **فاقد الأتربة** = `1 − الغلاف الحالي ÷ الغلاف بعد آخر تنظيف` (مع تصحيح تأخر الغلاف).
5. **الخسارة بالجنيه** = الفاقد × الإنتاج المتوقع × سعر الكيلووات ساعة، متراكمة منذ آخر تنظيف.
6. **القرار:** لما الخسارة التراكمية = تكلفة التنظيف يبقى التنظيف أمثل (لو الفقد خطي). الفاصل الأمثل `T* = √(2C ÷ (a·E·p))`.
7. **أعطال:** هبوط ≥15% لمدة 4 أيام متتالية = عطل/ظل (مش أتربة). إنتاج ≈ صفر = انقطاع. ارتفاع ≥5% = تنظيف/مطر.
8. **معايرة:** لو سجّلت تنظيفتين، المحرك بيعايِر الميل الفعّال تلقائيًا (بيصلّح أخطاء الميل/الاتجاه/الجو).

## شكل ملف القراءات (CSV)

```csv
date,kwh
2026-08-01,31.4
2026-08-02,31.1
```
`kwh` = إنتاج اليوم الكامل بالكيلووات ساعة (من شاشة الإنفرتر). عمود اختياري `kt_sat` (وضع الطقس التجريبي).
تواريخ التنظيف بتتكتب في الشريط الجانبي (YYYY-MM-DD). **سجّل أي تنظيف**: ده أهم عامل في الدقة.

## نتائج الدقة (على المحاكاة)

| الحالة | متوسط خطأ الفاقد | نسبة الحالات ≤ 3 نقاط |
|---|---|---|
| النموذج مطابق، تنظيف مسجّل (100 سيناريو) | 1.37 نقطة | 92% |
| بدون تسجيل التنظيف | 1.56 | 87% |
| نظام 30 كيلووات | 1.36 | 91% |
| **نموذج غير مطابق** (ميل/جو/فواقد مختلفة)، تنظيفة واحدة | **9.39** | **0%** |
| نفس الحالة بتنظيفتين **بدون** معايرة | 5.25 | 10% |
| نفس الحالة بتنظيفتين **مع** المعايرة التلقائية | **1.31** | 87.5% |

- كشف الأعطال: 100% من الأعطال المحاكاة اتكشفت، مع **6% إنذارات كاذبة** (فترات غيوم طويلة).
- وضع الطقس الخارجي (`kt_sat` بخطأ 4%) ما حسّنش الدقة (2.74 نقطة)، فهو تجريبي وغير مفعّل افتراضيًا.

### حساسية الدقة لأخطاء الإعدادات (تنظيفة واحدة)

| الخطأ في الإعداد | الانحياز (نقاط) |
|---|---|
| فواقد النظام، الحرارة، بخار الماء | ≈ 0 (بيتمتص في خط الأساس) |
| الاتجاه منحرف 20° | +0.7 |
| الميل خطأ 5° | **+2.7** |
| الاتجاه منحرف 40° | **+4.3** |
| جو أغبر (AOD 0.25 بدل 0.12) | **+5.0** |
| الميل خطأ 10° | **+6.5** |

**الخلاصة:** الدقة بتعتمد على صحة الميل والاتجاه. قيسوهم بتطبيق ميل في الموبايل، وسجّلوا تنظيفتين علشان المعايرة.

## حدود صريحة (لازم تتقال في أي عرض)

1. الأرقام دي على **محاكاة** بيتم توليدها بنفس نموذج pvlib المستخدم في المحرك (مع تشويش وانحياز)، فهي أفضل من الواقع غالبًا. الواقع هيكون أصعب.
2. الغبار في الجو (مش على الألواح) بيقلّل الإشعاع وبيظهر كأنه فاقد أتربة. المحرك مش بيفرّقهم.
3. أي عطل بيستمر أكتر من أسبوع بيخبّي الأتربة خلاله (مش قابلة للقياس وقت العطل).
4. فاقد أقل من ~3% غير قابل للقياس بثقة (نعتبره "لا إجراء").
5. افتراض الفقد الخطي (المعادلة المثلى) تقريبي، والواقع فيه مطر وعواصف.
6. الواجهة اتجرّبت آليًا (AppTest، بدون أخطاء) لكن ما اتشافتش بصريًا في متصفح: افتحها وراجعوا الشكل.

## الخطوة الجاية (للانتقال من محاكاة إلى واقع)

1. اجمعوا قراءات يومية من 3 إلى 5 أنظمة حقيقية (حتى لو أهل/جيران) لمدة 3 إلى 4 أسابيع.
2. اعملوا **اختبار تنظيف**: قدّروا الفاقد قبل التنظيف، نظّفوا في يوم صافٍ، وقارنوا الإنتاج قبل وبعد. الفرق بين التقدير والارتفاع الفعلي = الدقة الحقيقية.
3. جرّبوا `engine/pvgis.py` لو عايزين مقارنة بالمتوسط المناخي.
4. أضيفوا قراءة صورة الإنفرتر (Gemini Vision) وتذكير واتساب.
